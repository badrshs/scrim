Scrim plays a movie with explicit nudity covered by a box or a blur, composited
live as it plays. The original file is never modified and never re-encoded.

Everything runs on your machine. No uploads, no telemetry, no update checks,
not even a web font.

## Which download

| | |
|---|---|
| **`Scrim_0.1.0_x64-setup.exe`** | The installer. Pick this one. |
| **`scrim-0.1.0-windows-x64-portable.zip`** | Unzip and run `scrim.exe`. Installs nothing. |

Windows 10 or 11, 64-bit. Both carry their own mpv, ffmpeg, ONNX Runtime and
detection model, so nothing else is needed. Tested by copying the portable
folder to a machine with none of those installed.

## What it does

- **Scan once, then watch.** A scan writes a plan next to the movie and
  playback starts fully covered from the first frame.
- **Or start now.** Live detection runs ahead of playback and fences you behind
  it: seeking past the analysed point snaps back, and playback pauses on its
  own rather than showing you a frame nobody has looked at.
- **Cast to a Chromecast** with the cover burned into the pixels before
  anything leaves the machine. The television never gets the original file, so
  there is nothing on it to bypass.
- Black box, white box, or three strengths of blur, switchable mid-film with no
  restart and no rescan.
- Subtitles, sync nudging, light and dark themes.

## Why is a fight scene covered?

Scrim cannot detect violence or blood. There is no classifier for either, only
five nudity labels. A covered fight is a false positive on bare skin.

While the picture is covered, the status bar names the reason:

```
● MALE_GENITALIA_EXPOSED 0.58   seen once · from 00:14:20
```

**seen once** in amber means a single sampled frame of evidence, which still
buys 15 seconds of covering. That is what most false positives look like.

Set **Settings → Ignore single glimpses** to 2. On the test film that took
covering from 87 spans and 10:06 of runtime down to 55 and 6:06, removing about
four minutes of spurious covering while keeping every sustained detection. It
applies immediately, with no rescan, because plans store what was *detected*
rather than what to cover.

## Honest limitations

- Detection is only as good as NudeNet. It misses brief flashes and
  occasionally flags a bare torso. This is a tool, not a guarantee about any
  particular film.
- Dense films get larger boxes. ffmpeg's expression parser gives up at 99
  nested spans, so above 90 Scrim merges into longer ones. The alternative is a
  filtergraph ffmpeg rejects, which would play the film uncovered.
- **Casting has never been tested against real hardware.** The code is there
  and unit-tested; nobody has pointed it at an actual Chromecast yet.
- Cast streams cannot be seeked or paused from the television.
- Windows only.
